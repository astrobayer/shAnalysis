I/O

shLowLevel.readMascon

Read JPL / CSR / GSFC mascon netCDF grids for comparison against the SH chain.

Syntax

mas = shLowLevel.readMascon('GRCTellus.JPL.200204_202512.GLO.RL06.1M.MSCNv03CRI.nc')

Description

Base-MATLAB ncread-based reader with auto-detection of the common variable layouts (lwe_thickness / lwe / water_thickness; lat/latitude; lon/longitude; time with “days since” units → decimal years). Returns lat (nlat,1), lon (nlon,1, 0..360), epoch (T,1) decimal years, ewh (nlat,nlon,T) as stored (check mas.units), units, name.

Latitude convention: mascon grids are typically geodetic. Synthesize SH fields on the mascon grid with LatType="geodetic" (or convert via shLowLevel.geodetic2geocentric) before differencing — skipping this biases mid-latitudes by up to ~21 km of latitude. Full comparison workflow: guide, “Comparing against mascons”.

Real files, and the two traps v3.8.2

Verified against the JPL RL06.3Mv04 CRI product (0.5°, 257 months, 46 MB): lwe_thickness(time, lat, lon), latitudes ascending −89.75..89.75, longitudes 0.25..359.75, time in days since 2002-01-01, units cm. The reader permutes to (lat, lon, time) whatever order it finds.

Dimension order differs between products. The synthetic test fixture writes (lon, lat, time); the real JPL file writes (time, lat, lon). A size check passes either way, so the only honest test is a geographic one — Greenland must lose mass over the GRACE era. Set SHX_MASCON_FILE to run that check against your own download.
Latitudes are returned as stored, and mascon grids are conventionally GEODETIC. This toolbox synthesises on GEOCENTRIC latitudes. The difference peaks near 45° at 0.19° — about 21 km, or 0.4 of a mascon cell. Convert with shLowLevel.geodetic2geocentric before comparing, or the comparison carries a mid-latitude shift that looks like a real discrepancy.
