shLowLevel.standardChain

Canonical GRACE/GRACE-FO post-processing in one call.

Syntax

[ts, rep] = shLowLevel.standardChain(folder)[ts, rep] = shLowLevel.standardChain(folder, Pattern="*.gfc*", Truncate=NaN, TN14=true, ...)

Description

[TS, REP] = shLowLevel.standardChain(FOLDER) encodes the standard chain as a single, correctly ordered entry point: 1. read all monthly solutions from FOLDER (shSeries.fromFolder) 2. replace C20/C30 with the SLR values (TN-14) 3. add the degree-1 (geocenter) coefficients (TN-13) 4. optionally subtract a GIA trend field 5. filter (Gaussian radius, a DDK, or a shLowLevel.designFilter W) The order matters (TN corrections BEFORE filtering, GIA on the corrected series) and getting it wrong is the classic beginner error this function exists to prevent. Every step is recorded in REP and in the series history; steps are skippable for sensitivity studies. Data files come from the persistent data folder by default (setup_shAnalysis fetches them) and can be overridden with explicit paths for reproducible pipelines.

Examples

From the help block
    [ts, rep] = shLowLevel.standardChain("D:/grace/monthly", ...
        Filter = "DDK3", Degree1 = "GFZ");
    disp(rep.steps')
Runnable (docs/apiExamples.json)
[ts, rep] = shLowLevel.standardChain("D:/grace/monthly", ...
    Filter = "DDK3", Degree1 = "GFZ");
disp(rep.steps')

GIAn x m-[]shLowLevel trend field (shCoefficients, [1/yr]) subtracted as (t - GIAEpoch) * GIA
GIAEpoch1 x 1doubleNaNreference epoch of the GIA trend (NaN: mean epoch of the series)
Filtern x m-"gauss300""none" | "gaussN" (N = radius [km]) | "DDKn" (n = 1..8, read from the data folder; fetch it once with shLowLevel.fetchDDK) | a W struct from shLowLevel.readDDK / designFilter
Tolerance1 x 1double0.05maximum |epoch difference| [yr] accepted when matching a TN-13/TN-14 record to a solution
OnMissing1 x 1string"drop"what to do with solution epochs the correction tables do not reach. The tables ALWAYS trail the solutions - a provider publishes TN-13 weeks after the monthly field - so the newest months of a fresh series are routinely uncovered and the old behaviour was to stop with an error. "drop" removes them and records it in REP; "error" restores the old behaviour. Dropping is the default because the only other option that keeps them would splice UNCORRECTED months onto corrected ones, which puts a step in the series exactly where people look for the newest signal
Quiet1 x 1logicalfalsesuppress progress output
