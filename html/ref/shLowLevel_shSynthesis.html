shLowLevel.shSynthesis

Spherical harmonic synthesis of a global/regional grid.

Syntax

[grid, lat, lon, P] = shLowLevel.shSynthesis(C, S, GM, R, latVec, lonVec)[grid, lat, lon, P] = shLowLevel.shSynthesis(C, S, GM, R, latVec, lonVec, Quantity='geoid', Nmin=0, Nmax=size(C,1)-1, ...)

Description

[GRID, LAT, LON] = SHSYNTHESIS(C, S, GM, R, LATVEC, LONVEC) synthesizes the disturbing-potential-derived quantity (default: geoid height) on the grid LATVEC x LONVEC (degrees) from fully normalized (ICGEM) Stokes coefficients C, S at the reference sphere r = R - or, with Surface = "ellipsoid", on the reference ellipsoid (v5.5.0).

Examples

Runnable (docs/apiExamples.json)
grid = shLowLevel.shSynthesis(g.C, g.S, g.GM, g.R, -89:89, 0:359);

Name-Value Arguments

NameSizeTypeDefaultDescription
Quantityn x m-'geoid'one of ('none' = dimensionless passthrough, kernel 1, no GM/R/kn enter - the clean way to synthesize raw coefficient fields such as kernels or masks): 'geoid' N = R * sum Pbar_nm (Cnm cos m lon + Snm sin m lon) [m] 'gravity_anomaly' dg = GM/R^2 * sum (n-1) Pbar_nm (...) [m/s^2] 'gravity_disturbance' dg = GM/R^2 * sum (n+1) Pbar_nm (...) [m/s^2] 'potential' T = GM/R * sum Pbar_nm (...) [m^2/s^2] 'ewh' equivalent water height using love numbers 'kn' [m]
Nmin0-0, Nmax (size(C,1)-1) degree range to include. Renamed from nmin/nmax in v4.0.0.
Nmaxn x m-size(C,1)-1maximum spherical harmonic degree
knn x 1-[]load Love number vector k_n (index 1 = degree 0), required for "ewh"; NOT supplied by default -- see note below.
rho_ave5517-5517average Earth density [kg/m^3] (used for "ewh")
rho_water1000-1000water density [kg/m^3] (used for "ewh")
Pn x m-[]precomputed Legendre array from a prior call/LEGENDREALF, for the identical latVec and nmax -- skips recomputing the recursion. No validation is done that latVec/nmax actually match; passing a mismatched P silently gives wrong results.
Methodn x m-'auto'"auto" / "direct" / "fft": FFT-along-longitude synthesis for uniform full-circle longitude grids; 'auto' picks it whenever applicable. The two differ only in the last step, along longitude, and neither is faster everywhere: FFT ran 1.40x faster at nmax 60 / 1 degree on A8 (the reduction alone), while on MATTHIASPC the whole call is 0-14 percent faster with direct across 13 sizes from nmax 30 / 1 degree to 360 / 0.5 degree (v5.12.2). 'auto' keeps FFT. (This row claimed "5-20x" until v5.5.0; it was never measured.) Symmetric latitude grids additionally reuse the Legendre recursion for +/-lat pairs via the parity relation.
MaxMemGB4-4Legendre-block memory budget before banding
hnn x m-[]load Love numbers h'_n, for deformation quantities
Height0-0evaluation height [m] above the evaluation surface: above R on the sphere, above r(phi) on the ellipsoid
Surface1 x 1string"sphere""sphere" | "ellipsoid". "sphere" evaluates at r = R + Height, bitwise as before v5.5.0. "ellipsoid" evaluates at r(phi) + Height, r(phi) the geocentric radius of the ellipsoid from shLowLevel.ellipsoidRadius, through the same (R/r)^p_n law Height uses. Only quantities with a radial law accept it: potential, gravity_anomaly, gravity_disturbance, gravity_gradient_rr. The geoid is refused deliberately: on the ellipsoid it also needs the latitude-dependent normal gravity gamma(phi), and correcting the radius alone would be half a correction. At high latitudes the ellipsoid lies INSIDE the sphere (21.4 km at the poles), so high degrees are amplified there - this is why the choice matters for gravity near the poles
SemiMajorAxis1 x 1double6378137semi-major axis of the ellipsoid [m], WGS84; used only with Surface = "ellipsoid"
Flattening1 x 1double1/298.257223563flattening of the ellipsoid, WGS84; used only with Surface = "ellipsoid"

Output Arguments

NameDescription
grid(nlat x nlon) double synthesized field in the units of the requested quantity
lat(1 x nlat) double geocentric latitude grid used [deg]
lon(1 x nlon) double longitude grid used [deg]
P(nmax+1 x nmax+1 x nlat) double Legendre array as returned by LEGENDREALF; pass it back via 'P' to skip the recursion. EMPTY in latitude-banded mode (MaxMemGB exceeded): the blocks are streamed and discarded, so request the 4th output only with a memory budget that fits the full array.

Error Identifiers

IdentifierRaised when
shLowLevel:shSynthesis:badInputC and S are not square matrices of equal size, or Nmax exceeds the coefficients supplied
shLowLevel:shSynthesis:badPa precomputed P does not match Nmax and the latitude vector
shLowLevel:shSynthesis:badMethodMethod="fft" on a longitude vector that is not uniform and full-circle
shLowLevel:shSynthesis:noRadialLawSurface="ellipsoid" for a quantity with no radial law (geoid, ewh, the mass and deformation quantities, none): a surface quantity cannot be moved off the sphere
