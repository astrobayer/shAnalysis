shLowLevel.estimateDegree1

Geocentre coefficients from GRACE itself (Swenson 2008).

Syntax

[d1, info] = shLowLevel.estimateDegree1(ts, ocean)[d1, info] = shLowLevel.estimateDegree1(ts, ocean, kn=[], OceanModel=[], LatDeg=-89:2:89, ...)

Description

[D1, INFO] = shLowLevel.estimateDegree1(TS, OCEAN) estimates the degree-1 coefficients C10, C11, S11 for every epoch of the series TS, using the method of Swenson, Chambers & Wahr (2008).

Examples

From the help block
    LN = shLowLevel.readLoveNumbers("loadLoveNumbers.txt");
    d1 = shLowLevel.estimateDegree1(ts, isOcean, kn = LN.kn);
    ts = ts.addDegree1(d1);            % same interface as TN-13

  See also shLowLevel.readTN13, shSeries.addDegree1,
  shLowLevel.oceanRMS.
Runnable (docs/apiExamples.json)
d1 = shLowLevel.estimateDegree1(ts, isOcean, kn = LN.kn, ...
    OceanModel = obpModel);
ts = ts.addDegree1(d1);            % same interface as a TN-13 table

Input Arguments

NameSizeTypeDefaultDescription
ts1 x 1shSeriesrequiredshSeries the solutions, degrees 2+ (a GSM series; any existing degree 1 is IGNORED, not added to)
oceannLat x nLon-requiredlogical, or a function handle f(latDeg, lonDeg) -> logical. true = ocean. This is user-supplied, like Love numbers: a wrong ocean domain changes the answer silently

Name-Value Arguments

NameSizeTypeDefaultDescription
knn x mdouble[]load Love numbers, degrees 0..nmax (REQUIRED - the degree-1 value is frame dependent and must not be assumed; see shLowLevel.readLoveNumbers for the frame conversion)
OceanModeln x mdouble[](nLat x nLon x T) double expected ocean mass in EWH [m] per epoch, or (nLat x nLon) for a static field, or [] for none. OMITTING IT BIASES THE RESULT: whatever ocean signal the model would have explained is then attributed to the geocentre instead (validated: up to 177% error on the reference problem)
LatDeg1 x :double-89:2:89, LonDeg (0:2:358) the evaluation grid. It only has to resolve the ocean domain and the three smooth degree-1 patterns, so a coarse grid is fine and fast
LonDeg1 x :double0:2:358longitudes [deg], lon in [0, 360)
Nmax1 x 1doubleNaNtruncate the observed field before evaluation (NaN: the series' own nmax)

Output Arguments

NameDescription
d1(1,1) struct exactly the layout shLowLevel.readTN13 returns - sigmas included, which shCoefficients.addDegree1 requires - so it drops straight into shSeries.addDegree1. Fields epoch, t0, t1 (T,1) double epoch and span bounds [decimal years] C10, C11, S11 (T,1) double the geocentre coefficients sigC10, sigC11, sigS11 (T,1) double their 1-sigma, from the ocean-fit residual propagated through the least-squares solution
info(1,1) struct fields cond (T,1) double condition number of the column-equilibrated design matrix per epoch - equilibrated so the number reflects the GEOMETRY of the ocean domain, not the units of the columns. A rising value warns that the domain is too small or too lopsided BEFORE the noise shows it oceanFraction (1,1) double area fraction used nPixels (1,1) double ocean pixels that entered the fit hasModel (1,1) logical whether an ocean model was supplied residualRMS (T,1) double of the ocean fit, in EWH [m]
