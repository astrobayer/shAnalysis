shLowLevel.synthesisPoints

Gravity field quantities at arbitrary 3-D points.

Syntax

val = shLowLevel.synthesisPoints(C, S, GM, R, latDeg, lonDeg, r)val = shLowLevel.synthesisPoints(C, S, GM, R, latDeg, lonDeg, r, Quantity="potential", Nmin=2, Method="auto", ...)

Description

VAL = shLowLevel.synthesisPoints(C, S, GM, R, LATDEG, LONDEG, RGEO) evaluates the spherical harmonic expansion POINTWISE at positions given by equal-length vectors of geocentric latitude [deg], longitude [deg] and geocentric radius [m] - satellite altitudes, scattered stations, profiles - including the upward continuation (R/r)^n that grid synthesis on the sphere cannot provide: potential T = GM/r sum_n (R/r)^n sum_m Pnm (C cos + S sin) disturbance dg = GM/r^2 sum_n (n+1)(R/r)^n ... ( = -dT/dr ) anomaly Dg = GM/r^2 sum_n (n-1)(R/r)^n ... Fully normalized coefficients, C(n+1,m+1) layout, geocentric latitudes (house conventions). Python-validated: pinned reference values at the surface and at 450 km altitude, and the radial derivative identity dg = -dT/dr to 3e-10 (tools/validate_sh pointwise block; pins in testCorrectness/testSynthesisPoints).

Examples

From the help block
    dg = shLowLevel.synthesisPoints(g.C, g.S, g.GM, g.R, ...
        [10; 12], [100; 101], (g.R + 450e3) * [1; 1], ...
        Quantity = "disturbance") * 1e5;   % mGal at 450 km

Name-Value Arguments

NameSizeTypeDefaultDescription
Quantity1 x 1string"potential""potential" [m^2/s^2] | "disturbance" | "anomaly" (both [m/s^2]; multiply by 1e5 for mGal)
Nmin1 x 1double2first degree included (0 evaluates the full field including the central term)
Method1 x 1string"auto""auto" | "direct" | "clenshaw" - which summation to use; "auto" chooses "clenshaw" once the point count reaches ClenshawFrom
ClenshawFrom1 x 1double1point count at or above which "auto" switches to "clenshaw". The default is 1 because MATLAB has NO crossover: benchPointsCrossover timed both paths at the same points and found "clenshaw" ahead at every count measured (P = 1..2000 at nmax 60 and 120, P = 1..200 at nmax 360; narrowest margin 2.0x). Until v5.1.1 this was 150 - the crossover of the NUMPY prototype (tools/dev/validate_points_clenshaw.py, "direct" winning at P <= 100), transplanted to a language where it does not hold, which sent every station list below 150 points down the slower path. Raise it to force "direct" (the bitwise path) for short lists; re-measure with benchPointsCrossover before changing the default on a new machine
MaxMemGB1 x 1double4memory budget for the "direct" path's Legendre block; the chunk size follows from it and from nmax. Ignored by "clenshaw", which never allocates one
