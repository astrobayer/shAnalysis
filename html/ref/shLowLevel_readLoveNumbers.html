shLowLevel.readLoveNumbers

Read load Love numbers from a user-supplied table file.

Syntax

[LN, info] = shLowLevel.readLoveNumbers(filename)[LN, info] = shLowLevel.readLoveNumbers(filename, Columns="auto", Nmax=[], Interp="none", ...)

Description

LN = shLowLevel.readLoveNumbers(FILE) parses a plain-text load-Love-number table (comment lines starting with %, #, ! or // are skipped; an optional header line naming the columns is recognized). The toolbox never hardcodes Love numbers - this reader turns YOUR loading-model table (PREM, Gutenberg-Bullen, ak135, ...) into the kn/hn/ln vectors the synthesis and deformation routines expect.

Examples

From the help block
    LN = shLowLevel.readLoveNumbers("prem_load.txt", Columns="n h l k", ...
             Nmax=96, Interp="pchip", InFrame="CE", OutFrame="CF");
    [up, no, ea] = g.deformation(latPts, lonPts, kn=LN.kn, hn=LN.hn, ...
             ln=LN.ln, Mode="points");

Input Arguments

NameSizeTypeDefaultDescription
filenamen x m-requiredchar/string path of the file to read/write (gzipped .gz accepted where documented)

Name-Value Arguments

NameSizeTypeDefaultDescription
Columns1 x 1string"auto"explicit column meaning, tokens from {n,k,h,l}, e.g. "n k h l" (overrides header detection)
Nmax1 x 1double[]verify coverage of degrees 0..Nmax and truncate; with sparse tables combine with Interp ("none")
Interp1 x 1string"none""none" | "pchip": fill degree gaps by shape- preserving pchip in log(1+n) - Farrell-style sparse tables (n = ...,32,56,100,...) become dense. Python-validated: max abs error 1.3e-4 (0.05% of curve range) reconstructing a smooth kn' curve from 15 Farrell-spaced samples. Interpolation stays inside the table span; extrapolation errors out.
InFrame1 x 1string""degree-1 reference frame of the FILE, and
OutFrame1 x 1string""requested output frame: "CE" | "CF" | "CM". Both or neither. Only degree 1 changes (Blewitt 2003 isomorphic frames): all of h1,l1,k1 shift by the same constant d: CE->CF d = (h1+2*l1)/3 CE->CM d = 1 + k1 CF->CM d = 1 + k1 (k1 in CF values) CM->CF d = (h1+2*l1)/3 (in CM values) Conversions TO "CE" from CF/CM are not recoverable from the table alone and error. Validated against the published PREM values: CE (-0.290, 0.113, 0.021) -> CF (-0.269, 0.134) and the exact identity k1(CM) = -1; the CF->CM->CF roundtrip is exact.

Output Arguments

NameDescription
LN(1,1) struct fields n (D x 1) degrees, ascending kn (D x 1) potential load Love numbers k'_n hn (D x 1) vertical (NaN if absent from file) ln (D x 1) horizontal (NaN if absent from file)
info(1,1) struct fields source (1,1) string the file it was read from columns (1,:) string the columns actually used frame (1,1) string the degree-1 frame declared interpolated (D x 1) logical which degrees were filled in rather than read
