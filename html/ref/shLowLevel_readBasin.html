shLowLevel.readBasin

A basin of a GravIS GeoJSON file as a region, by name.

Syntax

[region, info] = shLowLevel.readBasin(name)[region, info] = shLowLevel.readBasin(name, File="basins_rivbas.json")

Description

[REGION, INFO] = shLowLevel.readBasin(NAME) finds the basin NAME in the GravIS river-basin file shipped with the toolbox (data/gravis/basins_rivbas.json, 100 basins) and returns it as a REGION function handle, m = REGION(latDeg, lonDeg), 1 inside and 0 outside, that every region-taking function accepts (evalMask, basinKernel, slepianBasis, regionalBasis). The match is exact first, then case-insensitive, then a case-insensitive substring that only ONE basin contains - so "Elbe" finds "Elbe River" - and INFO.name says which basin was taken. NAME may also be a string array: then REGION is a (1,N) cell of handles and INFO a (1,N) struct array, all from one read of the file; an empty NAME (string.empty) takes every basin of the file, in file order - the form the GravIS chains use (twsChain, gravisRegionChain), so the toolbox converts GeoJSON rings in one place (A33). A substring two basins contain is refused rather than resolved.

Examples

From the help block
    [reg, info] = shLowLevel.readBasin("Elbe");
    idx = shLowLevel.shIndex(60);
    B = shLowLevel.regionalBasis(idx, reg, Type = "slepian");

Output Arguments

NameDescription

info(1,1) struct fields name (1,1) string the basin actually taken file (1,1) string the file it was read from names (N,1) string every basin name in the file rings (1,R) cell each ring as a (K,2) double [latDeg lonDeg], longitudes as in the file hole (1,R) logical the ring is a hole of its polygon polar (1,R) logical the ring winds around a pole polygon (1,R) double which polygon each ring belongs to properties (1,1) struct the feature's GeoJSON properties
