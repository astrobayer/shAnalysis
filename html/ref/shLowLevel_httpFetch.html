shLowLevel.httpFetch

Download a URL to a file with Retry-After-aware retries.

Syntax

info = shLowLevel.httpFetch(url, dest)info = shLowLevel.httpFetch(url, dest, MaxTries=4, BaseDelay=2, MaxDelay=60, ...)

Description

INFO = shLowLevel.httpFetch(URL, DEST) downloads URL to the file DEST. On transient failures (HTTP 429, 500, 502, 503, 504, or a network error) it retries with exponential backoff and jitter; when the server sends a Retry-After header (seconds or an HTTP-date), that value takes precedence over the backoff. Built on matlab.net.http because websave discards the response headers on error - which is exactly why polite retrying was never possible with it. Motivated by the 503 bursts the GravIS portal returns on bulk fetches (guide V7/V8 data); all toolbox fetchers route their downloads through this function.

Examples

From the help block
    info = shLowLevel.httpFetch("https://isdc-data.gfz.de/...", ...
        "C:/data/aux.dat", MaxTries = 5);

Name-Value Arguments

NameSizeTypeDefaultDescription
MaxTries1 x 1double4(1 x 1) total attempts before giving up
BaseDelay1 x 1double2(1 x 1) first backoff delay [s]; attempt k waits BaseDelay * 2^(k-1) plus up to 25% jitter
MaxDelay1 x 1double60(1 x 1) cap on any single wait [s], also applied to server-sent Retry-After values
Timeout1 x 1double60(1 x 1) per-attempt timeout [s]
WebsaveFallback1 x 1logicaltrue(1 x 1) after all matlab.net.http attempts fail WITHOUT ever receiving an HTTP status (a transport-level failure: proxy, TLS, or a stalled connection), try ONE websave, which uses MATLAB's webread network stack and may succeed where matlab.net.http cannot (observed on a machine where only websave reached ICGEM). Received statuses (404, 429, ...) NEVER fall back - the badStatus/failed contract holds
Quiet1 x 1logicaltrue(1 x 1) suppress the per-retry progress line

Output Arguments

NameDescription
info(1 x 1) struct with fields status (1 x 1) double final HTTP status code tries (1 x 1) double attempts used waited (1 x 1) double total seconds slept between attempts bytes (1 x 1) double bytes written to DEST transport (1 x 1) string present ONLY when the websave fallback ran (value "websave-fallback"); the normal path leaves the field absent, so test with isfield
