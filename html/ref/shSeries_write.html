shSeries.write

Export every epoch to its own ICGEM .gfc file.

Syntax

shSeries.write(obj, folder)shSeries.write(obj, folder, FileNames=string.empty(0,1), Comment="", Sidecar=false)

Description

ts.write(FOLDER) writes epoch k with g.write, through ts.at(k), so each file is what g.write writes for that epoch. The files are named after the series' names: NAMES(k) + ".gfc", unless FileNames says otherwise.

Examples

From the help block
    ts.write(outFolder, FileNames = "GSM-2_" + spans + "_mine.gfc");

Input Arguments

NameSizeTypeDefaultDescription
objn x m-requiredthe object the method is called on
folder1 x 1stringrequiredstring existing folder to write into

Name-Value Arguments

NameSizeTypeDefaultDescription
FileNames: x 1stringstring.empty(0,1)) (T x 1) string one file name per epoch, relative to FOLDER; empty uses NAMES + ".gfc"
Comment1 x 1string""forwarded to g.write
Sidecar1 x 1logicalfalseforwarded to g.write. Deliberately false here, where g.write defaults to true: a folder of epochs is meant to be read back as a series, and the default read pattern "*.gfc*" would pick up every "<file>.gfc.provenance.json" as well

Output Arguments

None.

Error Identifiers

IdentifierRaised when
shSeries:write:noFolderFOLDER does not exist - write does not create it
shSeries:write:badFileNamesthere is not one non-empty, unique file name per epoch (by default: the series carries no such names)
shSeries:write:epochNotInNamea WARNING, not an error: at least one file name will not bring its epoch back when the folder is read
